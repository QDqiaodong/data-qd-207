# 样本级特征血缘、缺陷与交付凭证契约

在[复核目录契约](review-contract.md)与[数据集发布账本契约](dataset-release.md)
之上扩展的**只登记依赖与引用**的能力。它回答两个问题：

1. 一份滑窗特征实际依赖了哪些原始样本、这些样本当时从哪份归档副本取来；
2. 当副本局部损坏或原始采样本身无效后，已经算好的特征与已交付凭证现在
   还能不能用。

本能力不读取、不解码波形或特征数值，不实现特征算法、模型训练、CLI 或页面；
目录里只新增节点声明、父窗口、缺陷区间和凭证选择这类引用数据。

## API 总览

全部规范方法位于已打开的 `ReviewDirectory` 句柄，返回值均为 JSON 可序列化
的新建对象，调用方改写返回对象不会影响目录内部历史：

```python
d.capture_waveform_input({
    "node_id": "R",
    "release_request_id": "pub1",
    "group_key": "e1",
    "station": "A",
    "interval": [100, 120],
})
d.register_window_feature({
    "node_id": "F",
    "length": 16,
    "parents": [{"node_id": "R", "offset": 0, "width": 5}],
})
d.record_sample_defect({
    "request_id": "def-r0-108",
    "scope": "receipt",          # 或 "physical"
    "target": "r0",              # scope=physical 时目标是台站 ID
    "interval": [108, 110],
})
d.feature_health("F")
d.issue_feature_certificate({
    "request_id": "cert-1",
    "usage": "train",            # 或 "blind"
    "selections": [{"node_id": "F", "intervals": [[0, 4)]}],
})
d.read_feature_node("R")
d.read_feature_certificate("cert-1")
d.check_feature_certificate("cert-1")
```

异常类型：参数与业务前置条件错误抛 `ValueError`（其子类 `LineageError`）；
未知节点/凭证分别抛 `UnknownNodeError`、`UnknownCertificateError`，它们同时
是 `ValueError` 与 `KeyError` 的子类。

## 坐标与长度口径

- 所有区间都是非空半开整数区间 `[lo, hi)`；`length`、`width`、`offset`
  与区间端点必须是严格整数，**布尔值一律拒绝**。
- 节点长度范围 `1..10^9`；原始节点输出位置 `i` 对应该站本地刻度 `a+i`，
  其中物理区间固定为 `[a, b)`、长度 `b-a`、输出域 `[0, b-a)`。
- 特征节点输出域始终为 `[0, length)`。
- 单目录容量：原始节点与特征节点各最多 32 个，缺陷与凭证各最多 64 条；
  不降低旧目录任何既有输入上限。

## 原始输入节点 `capture_waveform_input`

表示一次**重新实际取数**（目录本身不接触波形字节，只固定取数引用）：

- 入参字段固定为 `node_id, release_request_id, group_key, station, interval`。
- 引用的发布组必须是**本目录已成功发布**的；`[a,b)` 必须整体落在该组该站
  的 `sample_unions` 内，不允许借组外事件扩张范围，也不修改原发布清单。
- 只能选**当前完好的归档副本**：副本缺陷片段先被排除，重叠片段逐段选
  回执 ID 字典序最小者；在线原块不兜底，任何 `online`/`missing` 片段或
  物理采样缺陷都会整笔拒绝，失败的 `node_id` 不被占用。
- 即使原发布清单选择了其他回执，本次重取也允许改用当前完好副本（例如后
  补登的完好回执），但节点一经建立，其实际来源（回执、块、物理区间、
  发布组、用途）永久固定，永不替换。
- 节点固定继承发布组的 `train`/`blind` 用途。

## 特征节点 `register_window_feature`

字段固定为 `node_id, length, parents`；每个父项为
`node_id, offset, width`：

- 父节点必须已存在于同一目录；`width >= 1`、`offset >= 0`，均为严格整数。
- 输出位置 `i` 同时依赖每个父节点的完整窗口
  `[i+offset, i+offset+width)`；所有窗口必须完整落在父输出域内，
  不截断、不补零，否则整笔拒绝。
- 每个特征有一至两个**不同**父节点；重复父项拒绝。父项顺序无语义差别，
  打乱顺序的等价重放返回首次结果。
- 原始节点深度为零；特征深度为父节点最大深度加一，最多四层。
- 原始节点与特征节点**共用 `node_id` 空间且不可重定义**；新节点只能引用
  已存在节点，因此不可能引入环。
- 所有父节点的训练/盲测用途必须一致，特征继承该用途；不做用途仲裁。
- 登记只记录依赖：允许父节点已经局部无效，无效区间不会被隐去，而按下面
  的窗口规则继续传播。

## 两类不可混淆的缺陷 `record_sample_defect`

字段固定为独立的 `request_id, scope, target, interval`；缺陷一经接受
持续有效、可重叠，没有撤销或自动修复。

- `scope="receipt"`：目标是已有 `receipt_id`，区间用原始本地刻度且必须
  落在该回执范围内。它只说明**这一副本**在该区间不可信：
  - 只有固定使用该回执的原始输入在相交位置失效；使用其他回执（即使覆盖
    同一物理采样）的输入不失效。
  - 它按区间作用于 `query_sources`：先排除该回执的坏片段，再沿用“完好
    归档优先、回执字典序优先、在线原块兜底、否则缺失”的原契约；不会因
    一小段损坏舍弃整张回执或整块。
- `scope="physical"`：目标是已有台站，区间必须在该站采样域内。它说明
  **原始样本本身科学无效**：
  - 影响所有实际使用这些采样的原始输入，与回执、事件、校时版、发布请求
    是否相同无关；另一台站的相同本地刻度不受影响。
  - 它不改变 `query_sources` 对副本可读性的分类（完好回执仍显示为
    `archive`），也不豁免原块下线的归档义务。

换用完好副本只能建立**新的**原始输入与新的特征节点，不能修改旧节点的
实际来源；旧节点的无效影响按窗口规则继续传播，每条缺陷保留自己的精确
影响。

## 窗口传播与 `feature_health`

只要一个父窗口中有任意无效位置，该输出位置即无效；多父节点取所有依赖
影响的并集。传播完全在区间代数上完成，不逐点生成依赖或状态：

- 父输出位置 `p` 落在窗口 `[i+offset, i+offset+width)` 内时输出 `i`
  无效。对父无效区间 `[lo, hi)`，受影响输出反解为
  `i ∈ [lo-offset-width+1, hi-offset)`，再与本节点输出域求交。
- 父节点的全局缺陷不代表它的每个被引用窗口都无效；共享父节点、分支
  重新汇合、相邻半开区间（端点相接不共享样本）都按实际窗口依赖处理，
  不做“哪个节点引用过哪个节点”的整节点传播。

`feature_health(node_id)` 返回：

```json
{
  "node_id": "F",
  "kind": "feature",
  "output_domain": [0, 16],
  "invalid_intervals": [[4, 10]],
  "invalid_by_defect": {"def-r0-108": [[4, 10]]}
}
```

每组区间升序、无空段、不重叠，相邻同类影响合并；没有影响的缺陷不列出。
查询始终反映当前最新已成功登记的缺陷，而节点来源与依赖声明保持不变。

## 交付凭证 `issue_feature_certificate`

交付是受当前血缘约束的业务动作：

- 字段固定为 `request_id, usage, selections`；`usage` 为 `train`/`blind`，
  必须与每个被选节点的继承用途一致。
- 每个选择为 `node_id, intervals`：节点不重复，每节点区间集合非空且在
  输出域内；可交付原始或特征节点的一部分。区间重排、重叠拆分、相邻拆分
  按同一个采样集合规范化处理。
- **首次签发**用当前缺陷检查全部所选位置；任一位置无效即整笔拒绝，不会
  为其余选择先留凭证，失败请求 ID 可修正重试。
- 成功凭证固定请求 ID、用途、规范选择，以及解释这些选择所需的不可变
  节点依赖（`lineage_node_ids`、`raw_source_node_ids`）；依赖细节通过
  `read_feature_node` 公开读取，不展开逐输出点血缘。
- 新缺陷会撤掉受影响旧凭证的**当前可用性**；同一节点中不与缺陷相交的
  选择继续可用。凭证原文、节点来源声明与原发布清单都不能倒改。

读取接口的语义区别必须明确：

- `read_feature_certificate(request_id)` 只返回首次成功签发时固定的凭证
  原文；读成功**不代表当前获准取用**。
- `check_feature_certificate(request_id)` 返回当前是否仍可使用，并逐选择
  给出凭证真正选中位置内的当前无效区间与对应缺陷 ID（只检查选中位置）。
- 同 ID 等价重放始终返回首次成功凭证，即使它现在已不可用；新请求 ID
  必须重新按当前缺陷审核，无效选择拒绝。
- 本能力不重新占用或释放旧发布账本的训练/盲测样本，也不能借缺陷清除
  历史用途。

## 与来源查询、原块下线、数据集发布的衔接

- `query_sources`：副本缺陷按片段排除后再竞争覆盖；物理缺陷不改变
  `archive`/`online`/`missing` 分类。
- `request_offline`：只接受**完好归档**覆盖当前需求；已成功下线不倒改，
  原块不得重新上线。下线后才报告的副本损坏，在没有替代归档的片段上
  如实返回 `missing`。
- `preview_release`：在既有 `online_gaps`/`missing_gaps` 之外，每组新增
  `physical_quality_defects`（及 `has_physical_quality_defect` 等字段），
  显式区分物理质量缺陷与归档缺口；缺陷不改变候选分组、用途决定，也不
  把坏样本从事件范围中裁掉。
- `publish_release`：首次成功发布必须拒绝任何批准组中含物理缺陷的样本，
  只要一组不合格整个请求不生效；副本损坏则可改选完好归档后用原请求 ID
  重试，仅在线覆盖仍不得发布。旧成功发布的读取与等价重放原样返回旧清单。

## 持久化、幂等与崩溃重开

复用复核目录的 journal/LOCK 机制与本地单写者语义，新增四类 journal 记录：
`raw_node`、`feature_node`、`defect`、`certificate`。各类操作有独立 ID
空间，但两类节点共用 `node_id`。

- 所有业务校验在 journal 追加前完成；非法依赖、未知身份、越界、错误
  用途、重复父项等都不会留下部分状态。
- 记录先写 JSON 行并 fsync，再写 `COMMITTED` 标记并 fsync：提交前中断
  整体回滚（ID 未占用，可重试）；提交后应答丢失时，重开用同一 ID 重放
  只取回原成功结果，journal 中不产生第二条。
- 成功 ID 的等价重放不重复生效；同 ID 不同内容拒绝。重开以 journal 为
  唯一事实来源重放，`state.json` 只是派生缓存（含血缘计数摘要），缺失
  或陈旧都不影响恢复结论。
- 旧目录首次打开本能力时没有任何缺陷或特征历史；无缺陷时旧场景行为
  完全不变。

## 明确不做

- 不读取、复制、解码波形或特征字节，不实现特征算法与模型训练；
- 不逐采样点展开输出域，不用手写 mask 绕过发布与回执链路；
- 不提供 CLI、页面或粗粒度站级可用性标志；
- 不修改归并、复核、事件编目、回执与旧发布清单的既有行为。
